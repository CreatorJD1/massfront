# MASSFRONT — Review, 1 Aug 2026 (v1.19.0)

Four-dimension review: engineering, release readiness, design/balance, mobile UX.
Eight specialist reviewers → 56 raw findings → deduplicated to 26 → each sent to an adversarial
verifier told to **kill** it. **23 survived. 3 were killed.** A final completeness pass then found six things nobody had opened —
including one that forced me to retract a claim (see Correction, below).

Legend: **[V]** verified line-by-line by hand · **[A]** survived adversarial refutation.

## Ship blockers — all [V]

1. **No account deletion → App Store 5.1.1(v) rejection.** Auth worker routes are exactly
   `/health /login /logout /me /register /save`; `DELETE` is not even in the CORS allow-list. The profile
   screen's DELETE removes a *local* profile only. Meanwhile `authportal.js` renders **CREATE ACCOUNT**
   and `assets/auth.json` ships a live `syncUrl`. *Fix:* `DELETE /account` (cascade `saves`, `sessions`)
   + two-step confirm in the account panel.
2. **Nothing here can be uploaded to Google Play.** No `signingConfig`, no `bundleRelease`, no `.aab`
   anywhere in the repo; `release {}` has no signing config so `assembleRelease` emits unsigned.
   Play has required an `.aab` for new apps since Aug 2021.
3. **`tools/shrink-apk.sh` yields an APK that cannot install on Android 11+.** *Both* repack branches —
   `zip -qr9` (line 23) and the Windows `jar --create` fallback (line 30) — deflate `resources.arsc`,
   which the platform requires stored uncompressed since API 30
   (`INSTALL_PARSE_FAILED_RESOURCES_ARSC_COMPRESSED`). It also strips the 16 KB page alignment Play has
   required since 1 Nov 2025 for targetSdk 35+; this project targets **36**. AGENTS.md still calls the
   script MANDATORY — that line is now a trap.
4. **No `PrivacyInfo.xcprivacy`**, no `NSUserTrackingUsageDescription`, and `MARKETING_VERSION = 1.0`
   in both configs while the app ships 1.19.0.

## Two-line fixes with outsized payoff

```js
// src/game/sim.js — inside spawnUnit()'s reset block
umarch[i]=0; uhaz[i]=0;
// src/game/ai.js — inside aiSetup()
AI.stall=0;
```

- **[V][A] `spawnUnit()` never clears `umarch[]`.** I enumerated every per-unit typed array against what
  spawn resets: 18 reset, 4 not. `umov` is rewritten per frame, `uhaz` decays, `upx1` needs a
  coincidence — `umarch` **persists**. `freeList` is one pool across all three teams, so a dead AI
  marcher's slot hands a *player* unit a permanent march order: acquisition collapses to
  `min(T.rng*rngM+20,150)` (`sim.js:2354`) and the goal pins to its own spawn point (`sim.js:2387`).
  Only `resetWorld` clears it. Symptom: "some of my units just stand there."
- **[V][A] `AI.stall` survives across matches** (`ai.js:467`, not reset in `aiSetup()`). A match that ends
  mid-starvation carries the residual into the next one and corrupts **exactly one decision** — the first
  wave gate. If the residual meets the new difficulty's patience cap the AI throws ~4 units at you.
  This is HANDOFF §3's "AI must not attack without an army", reintroduced across the match boundary.

## Engine and simulation

- **[V][A] Acquisition hard-capped at 616 wu while the game asks for 830** (`sim.js:362`).
  `cr = min(14, ceil(rad/CS))`, `CS=44` → 616 guaranteed, ~659 absolute ceiling. Aggro is
  `rng*1.9 + 70`: Bombard (400) → 830, Dreadnought (290) → 621. The verifier added the consequences:
  this nullifies **Bastion Mk2's "+20% range"** (520→624, already past the cap) and the **Uplink's
  advertised "+35% tower range"**. The in-code comment ("14 cells ≈ 616wu — covers siege artillery") is wrong.
- **[V][A] Ten call sites pass `Math.PI/2` as a yaw to `cyl()`/`tube()`, which take no rotation.**
  `cyl(...,cap)` treats the 9th arg as a truthy cap flag; `tube()` has no 9th parameter. Rings build in
  x/z and extrude strictly along **+y**, so `mdlLancer()`'s 13-unit "gauss rifle rail" and
  `mdlBasilisk()`'s 11-unit barrel are vertical masts. Verifier scoping: **purely cosmetic** — nothing
  crashes and no gameplay, collision or aim path reads this geometry.
- **[A] Ground shadows ignore fog of war** (`render3d.js:59–108`). `drawShadows()` emits a decal for every
  live building and unit regardless of vision, so unscouted enemy waves are legible as moving blobs whose
  count, size (`T.size*0.70`) and heading all read correctly. Scouting given away for free.
- **[V][A] `ecoFlush()`'s "drop it" branch is an infinite main-thread loop** (`economy-net.js:225`).
  `continue` skips the `shift()`. Dead code in the shipped build (only `kind:'grant'` is queued) but the
  queue is persisted to localStorage and the type comment already documents `'grant'|'spend'`.
- **[V] `boot.js` and `assets/data/manifest.json` disagree on load order** — idx 17–20 are
  `hazards, offline, audio, assetpack` vs `offline, audio, assetpack, hazards`. Harmless today; nothing
  validates it. *Fix: assert the two lists match inside `tools/bundle.mjs`.*

## Backend

- **[A] The rate limiter is a non-atomic COUNT-then-INSERT, in both workers** (`auth:176`). N concurrent
  requests all read the pre-insert count and all pass. Verifier scoping: amplification, not bypass — the
  window saturates after the burst.
- **[A] Two concurrent `/spend` calls charge twice, advance the tier once** (`economy:297`). `nextTier`
  is computed from a read outside the D1 batch and committed with unconditional `SET tier=excluded.tier`.
  800 cores debited for one tier. Not live yet — fix before it is.
- **[A] The OTA channel has no code signing** (`updater.js:219–236`). The manifest supplies version,
  `base` origin *and* the SHA-256 digests as one self-attesting document, so the hash proves the download
  matches the manifest and nothing more. The sole trust anchor for code `boot.js:84` executes as classic
  scripts in the WebView is **write access to the R2 bucket**. Sign the manifest with a key in the binary.
- **[A] Cloud save push fails open, and there is no version history** (`authportal.js:299`). An empty
  `catch(e){}` leaves `cloudWeight` at `-1`, skipping the overwrite confirmation. The server keeps one
  save row per user with no version guard (`index.js:339`, `schema.sql:46`).
- **[A] `confirmBoot()` runs before the first frame** (`main.js:474–476`) — before `dt`, the sim tick,
  `camTick` and `render()`. A patch that loads its scripts and dies on its first real frame gets marked
  *good* and is never rolled back, defeating the probation protocol `boot.js` documents so carefully.
- **[V] `PBKDF2_ITERATIONS = 100000`** vs OWASP's ~600,000 for SHA-256 — and the upgrade-on-login
  machinery to change it already exists.

## Design and balance

- **[V][A] The setup screen's ☠1/☠2/☠3 wildcard button advertises a reward it cannot pay.**
  `index.html:287` still says "+35% XP & cores each", but payout moved to
  `payoutMult() = threatReward() * opModMult()` and `opModMult()` only counts `META.opmods` — modifiers
  *chosen in Operations*. Dice-rolled wildcards set the `WC` flag and contribute **zero**. (Nuance from
  the verifier: not literally ×1, since threat level still scales it.)
- **[V][A] `startWeekly()` overwrites your saved Operations modifiers and never restores them**
  (`endgame.js:131`). `opmods` appears in exactly two places in the tree. Every later skirmish carries
  the weekly's modifiers *and* their inflated `payoutMult`, corrupting `matchScore` / `META.bestScore`.
- **[V][A] HANDOFF §4's #1 known issue quotes stale numbers.** Two independent recomputations against
  live source agree that Rhino is **not** the outlier (HANDOFF's 0.702 dpc / 7.95 hpc are 1.12.0 figures;
  current is ~0.559 / 6.154, 4th of 22). They disagree on the winner — my normalisation
  (`cost = mass + 0.25·energy`) puts **Vulture** at 3.15× median damage-efficiency, the verifier's
  raw-mass normalisation puts **Pyro** at 1.89×. Both are tier 1 and both sit above Rhino either way.
  **Striker is still ~2.4×**, not the 1.4× HANDOFF records. And **tier 3 is upside-down** — Basilisk
  (0.79 combined) and Harbinger (0.67) lose on both axes to half the tier-1 roster.
- **[A] TITAN is a genuine outlier and part of it is undocumented** — 17.78 hp per mass (2.5× the best
  armed chassis), the cheapest build-time-per-mass, no energy offset, plus a **210-damage AoE stomp**
  (`sim.js:94`, fired at `sim.js:2440`) that appears in no UI and bypasses the weapon-vs-armour matrix.
- **[A] Shattered Isles' squall lands every strike on one point** (`hazards.js:200–205`). All 2/3/5 cells
  call the deterministic `hazPickMass()` in one synchronous loop; only a ±70 jitter separates them.
- **[A] The terminal Development node pays out nothing.** EMP Charge is unimplemented and the 1500-core
  *Weaponised Relics* node gates only that module, so the whole XENOLOGY tip is dead
  (`develop.js:93–94,147`). Its upkeep would exceed maximum isotope income even if it existed.

## Correction, and what the review itself missed

A final agent was asked what eight reviewers had failed to open. It found six gaps; I re-ran each
experiment myself. One contradicts a claim in the first version of this document.

### [V] Retraction: offline does not hold, and my instrumentation is why I said it did

My first request logger recorded only responses with `status >= 400`, so successful outbound calls were
invisible. Re-measured with a full `p.on('request', …)` listener on a cold boot, clean profile, no account:

```
GET https://massfront-update.jasondixon1994.workers.dev/packs.json?t=…
GET https://massfront-update.jasondixon1994.workers.dev/update.json?t=…
```

Both fire within ~4 s of launch, before any account exists and before any consent or privacy notice —
IP and request metadata leaving the device on first run for **every** install. That is precisely what
Play's Data Safety form and the iOS privacy manifest's `NSPrivacyCollectedDataTypes` ask about, and in
the EU it is a pre-consent transfer.

**Second hole:** `src/account.js` is a 22 KB second account-and-sync stack that nobody opened. Its
`syncPush()`/`syncPull()` POST the whole career to the live worker, and it contains **zero** references
to `netAllowed`/`netFetch` — against 1 in `authportal.js`, 2 in `updater.js`, 5 in `economy-net.js`.
`offline.js`'s own header calls itself "the single gate all four ask before reaching the network." It is not.
*Fix:* route `account.js` through `netFetch()`, gate the launch-time checks behind a first-run notice, and
re-measure the honest way before writing "offline verified" in HANDOFF again.

### [V] WebGL context loss is unhandled — the game looks alive and is silently dead

Grep for `webglcontextlost` / `webglcontextrestored` / `isContextLost` across `src/` and `boot.js`:
**nothing**. `gl.js:28` is `const gl = cv.getContext('webgl2', {...})` with no null check. I forced a loss
with `WEBGL_lose_context`: `gl.isContextLost()` went true, **zero page errors** were raised, and the
screenshot four seconds later shows the menu fully intact and fully interactive with only the 3D backdrop
gone to flat black. Nothing tells the player anything is wrong; they tap PLAY and get a dead canvas.

Android WebView drops the GL context on backgrounding under memory pressure as *normal behaviour* — this
is what happens when someone takes a phone call mid-match. A blocklisted driver returns `null` from
`getContext`, which faults on the first `gl.*` call with no fallback at all.
*Fix:* a `webglcontextlost` handler (`preventDefault()` + pause) with either a rebuild-on-restore path or
an honest "graphics context lost — tap to restart" overlay, plus a null guard at `gl.js:28`.

### [V] Ads ship **enabled** — this is an ad-supported app for store purposes

```js
const AD_CONFIG = { provider: 'local' };
const AD_PROVIDER = AD_CONFIG.provider === 'network' ? new NetworkAdProvider({}) : new LocalAdProvider();
```

HANDOFF §4 #4 says ads are "scaffolded, not live." True of the *network* provider, false of what a player
sees — `LocalAdProvider` serves the bundled creatives from `assets/ads/` in every build shipping today.
That changes Play's "contains ads" declaration, the Data Safety answers and the App Store age rating.
`src/adboards.js` (38 KB) is the largest file nobody opened; `docs/ADS.md` (18 KB) was never checked
against it. Decide before submission whether v1 ships boards on, and whether there is a player-facing switch.

### Three more gaps

- **No CI runs the syntax gate.** `.github/workflows/ios-ipa.yml` is the entire CI surface and triggers on
  `workflow_dispatch` and `v*` tags only — nothing on push or PR. The duplicate-global crash AGENTS.md says
  "has bitten us four times" is guarded by human discipline alone. A push/PR job running `bundle.mjs`,
  `pack-www.mjs`, the boot/manifest order assertion and a headless boot that fails on any `pageerror`
  takes about 40 seconds.
- **The load-order divergence is worse than framed above.** `pack-www.mjs` validates only `boot.js`'s
  MANIFEST, `bundle.mjs` reads only `manifest.json`, `make-manifest.py` writes `update.json` from
  `manifest.json`, and `runBundle()` prefers the bundle's own order — so a fresh install,
  `dist/massfront.html` and an OTA-patched device can execute the same 34 scripts in **three different
  orders**, each blessed by a different tool. Latent today only because `hazards.js` declares consts.
- **The save layer has no schema version and swallows quota failures.** `metaLoad()` (`meta.js:45`) does
  `Object.assign(META, o)` over the defaults and hand-repairs three fields; no version marker, no migration
  function anywhere. `metaSave()` is `try{…}catch(e){}` — a `QuotaExceededError`, which WKWebView produces
  under storage pressure, loses the career silently.

## On the new `.mfsave` format

Careful work: magic bytes, schema field, explicit length, SHA-256, constant-time compare, 5 MB ceiling,
envelope validation. One thing to be clear-eyed about — the digest ships inside the file it protects, so
it proves **integrity, not authenticity**. A crafted `.mfsave` with arbitrary XP/cores hashes valid. Fine
while currency is client-side, but it is a second import path into `META`: when the economy worker goes
live the server must treat an imported save as a claim, not a fact.
