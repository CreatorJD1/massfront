## 1. Fix this today: every map name is clipped at both ends

The battle-setup map picker renders:

```
GUARD VA   ·   HLAND SC   ·   TTERED IS   ·   ELIC BASI
```

Those are *Van**guard Va**lley*, *Hig**hland Sc**ar*, *Sha**ttered Is**les*, *R**elic Basi**n*.
Measured with a Range over the text node, not inferred:

```
"Vanguard Valley"    text 132.7px   box  71px   overflow:hidden  text-overflow:ellipsis  white-space:nowrap
"Shattered Isles"    text 132.7px   box  71px
"⛰ FAULT COLLAPSE"   text 115.6px   box  57px
```

**Why the ellipsis doesn't save it:** the label is centred in a box about half its width, so it
overflows left *and* right. `text-overflow:ellipsis` only renders on the trailing edge — with
symmetric overflow you get a hard cut at both ends and no ellipsis at all, and the result reads as a
different word. The hazard labels are left-aligned so they do degrade gracefully (`🌪 DUST …`,
`▲ FAULT…`) — uninformative at 57 px, but honest.

**Fix:** wrap `.mNm` to two lines, drop it to ~9 px, or widen the card. If it must stay one line,
`text-align:left` at minimum so the ellipsis works and the *start* of the name survives —
"Vanguard V…" is a map name; "GUARD VA" is not.

## 2. Retraction: the PLAY button is fine

The v1.31.0 check reported "the PLAY button clips its own label at 360 px." **That was wrong.**
It flipped between widths across runs, which is not how a layout bug behaves, so I measured the
label directly instead of trusting `scrollWidth`:

```
412px:  label 73.8px   box 204px   scrollWidth 319   ::after left: 265.188px
360px:  label 73.8px   box 204px   scrollWidth 204   ::after left: -60px
```

`▶ PLAY` is 73.8 px in a 204 px box and has never been truncated. The 319 px came entirely from
`.mbtn::after` — the animated shine sweep — counted as content because it lives inside an
`overflow:hidden` box. Every clipping claim in this document is now confirmed by a Range measurement
over the actual text node.

## 4. The OTA payload tripled

| Version | OTA payload | APK |
|---|---:|---:|
| 1.29.0 | 8.12 MB | 21.2 MB |
| 1.30.0 | 8.13 MB | 21.2 MB |
| 1.31.0 | 8.37 MB | 24.1 MB |
| **1.32.0** | **25.75 MB** | **36.9 MB** |

`bundle-update.mjs` ships the whole payload every time, not a delta — so a player on mobile data now
downloads 25.75 MB for a point release, and the next one will be at least that. The APK grew 53% in
one version. Neither is wrong on its own; both are worth a decision before they become the normal size.

## 5. Credit where it's due

`releases/MASSFRONT-v1.31.0-release-record.md` is the preflight actually executed, and it is better
than most shipped release processes:

- The immutable OTA payload was published and verified **before** the three manifests switched
  atomically, then the live manifest was fetched and its pinned payload re-hashed.
- The published APK was re-downloaded to a fresh file and its SHA-256, package, version, v2/v3
  signature, signer certificate and alignment all reverified against the local build.
- Staging identity confirmed for 40 canonical files across *both* `www/` and the Android Capacitor
  directory — closing the stale-staging blocker from your own preflight.
- All nine soundtrack files matched every indexed size and SHA-256.

The release channel is in good shape. What is not moving is the defect list.
