# The voice pack

162 rendered takes — KEEN's 54 narration lines plus command radio for the four
factions — travel on the on-demand asset-pack channel, **not** in the OTA payload.

`tools/bundle-update.mjs` inlines the 44 sources and six PNGs and nothing else, so
a player who takes the v1.32.41 update gets every voice code path and no audio.
The pack is what makes those code paths reachable. Without it `audLoad()` 404s,
`voPlay()`'s `onMiss` fires, and `speakVoice()` falls through to
`speechSynthesis` — a **silent no-op on Android WebView**, which is the exact
failure this release exists to fix.

---

## What the client expects

`src/assetpack.js` derives the pack endpoint from the update URL by stripping
`/update.json…` off it. With the official channel that leaves
`https://huggingface.co/datasets/CREATORJD/massfront-releases/resolve/main`, and
the client then asks for exactly two shapes of URL:

| Client request | On the channel |
| --- | --- |
| `<endpoint>/packs.json` | `packs.json` at the repo root |
| `<endpoint>/pack/voice/<file>` | `pack/voice/<file>` |

`pack/` is singular for the payload; `packs.json` is the index for **every** pack.
Music already ships on the same convention from `pack/music/`.

The index entry looks like this, matching what the channel already serves:

```json
{ "version": 1,
  "packs": {
    "voice": { "label": "…", "bytes": 5441415,
               "files": [ { "name": "keen_greeting.ogg", "size": 63075, "sha256": "…" } ] } } }
```

Three things about that shape are load-bearing:

- **`size` is part of the cache key.** Stored blobs are keyed `voice/<name>:<size>`,
  so a re-rendered take re-downloads automatically and a wrong size either
  re-downloads forever or serves a stale blob. The sizes must agree with
  `assets/audio/voice.json`.
- **File names are `<stem>.<ext>`, flat.** `src/audio.js` resolves a take with
  `packURL('voice', name.slice(6) + '.' + AUD.ext)` — no directories, no faction
  prefix beyond what is already in the stem.
- **Both containers, always.** Every take ships `.ogg` *and* `.m4a`. AAC is the only
  lossy codec iOS decodes; open-source Chromium builds have no AAC decoder at all.
  `audExt()` asks the browser at runtime, so a pack carrying one container is
  silent on one platform. The client cannot fall back — pick wrong and there is
  nothing to pick from.

`sha256` and `label` are publisher-side; the client reads neither. They are in the
existing scheme, so the tools keep writing them.

`assets/audio/voice.pack.json` is **not** this file. It is a *fragment* generated by
`tools/make-voices.py` for a human to merge (`{packs:{voice:{bytes,files}}}`, no
`label`, no `sha256`, no other packs). `tools/build-voice-pack.mjs` supersedes it.

## Rebuild

```sh
node tools/build-voice-pack.mjs            # rebuild from assets/audio/voice
node tools/build-voice-pack.mjs --from-live # …and refresh the other packs' entries
```

Produces a local copy laid out exactly like the channel:

```
assets/packs/packs.json          -> <endpoint>/packs.json
assets/packs/pack/voice/*.ogg    -> <endpoint>/pack/voice/*
assets/packs/pack/voice/*.m4a
```

`assets/packs/` is **publisher output, not app content** — exclude it from whatever
copies `assets/` into the Capacitor `www` (`tools/pack-www.mjs`). Every byte in it
is already in the installer at `assets/audio/voice/`; packaging both puts the same
5.19 MB in the APK twice. `tools/bundle.mjs` and `tools/bundle-update.mjs` are
unaffected — they only read `assets/data/manifest.json` order.

The build refuses to write anything if a take referenced by `assets/audio/voice.json`
is missing, is under 1 KB, or disagrees with the manifest's recorded size. It packs
only takes the bank references — a stray file in `assets/audio/voice/` is reported
and left out.

**It merges the index, it does not regenerate it.** `packs.json` also carries
`music`, whose 16 MB live on the channel and not in this repo. Rebuilding the index
from local directories alone would drop that entry and unpublish the soundtrack for
every player. Use `--from-live` when the other packs may have changed under you;
otherwise the entries already in `assets/packs/packs.json` are carried through
untouched.

> `tools/publish-assets.mjs` is the older publisher and targets a Cloudflare R2
> bucket through `cloudflare/massfront-update`, which is not in this tree. Its
> `PACKS` map points at `assets/audio/music`, which is also not in this tree, so
> running it today uploads `{"packs":{}}` and unpublishes both packs. Use the two
> tools below instead.

## Verify — no network, no publish

```sh
node verifyvoicepack.mjs
```

34 checks in three parts: the staged pack against the voice manifest; seven
negative controls that must fail (missing take, ogg-only pack, wrong size, wrong
hash, a padded stub, an indexed-but-absent file, no pack at all); then the real
`src/assetpack.js` — verbatim, not a reimplementation — pointed at a local HTTP
copy of the channel. That last part downloads all 324 files into IndexedDB,
resolves a `blob:` URL for every take the game will ask for, reads each blob to
confirm the byte count, decodes a KEEN take to non-silent PCM, confirms a second
pass re-downloads nothing, confirms the offline gate refuses the network, and
confirms an index naming a file the channel lacks fails loudly.

Remove one `.m4a` from `assets/packs/pack/voice/` and the run exits 1 with seven
failures, including 174 unresolved takes from the live client. A missing take
cannot pass this quietly.

## Publish

```sh
python3 tools/publish-voice-pack.py --dry-run   # check everything, upload nothing
python3 tools/publish-voice-pack.py             # 324 files, then the index
```

Needs `HF_TOKEN` (or `/mnt/user-data/uploads/huggingface/token`, same as
`tools/publish.py`).

Files go up **first**, `packs.json` **second**, as two commits — the same ordering
rule `tools/publish.py` follows for releases. Clients poll the index; if it named a
file that was not on the channel yet, every launch in between would 404 mid-download
and show "AUDIO PACK UNAVAILABLE". Payload first makes that window harmless.

The publisher re-verifies the staged pack, refuses to publish an index with fewer
packs than the channel already serves (`--allow-drop` to override), and afterwards
reads the index and a spread of real audio files back through the same URLs the game
uses, comparing sizes and hashes. An upload that succeeded is not a publish; a
publish is what a client can see.

Order for the release as a whole: publish the voice pack **before or alongside**
`tools/publish.py`. The pack is inert until a build asks for it, and a build that
asks for a pack that is not there is the failure being fixed.

## The player who declines, or cannot download

Nothing in the pack system is required, and this must stay true.

- **Declines.** `src/assetpack.js` offers once on the start screen with the size
  stated up front ("AUDIO PACK AVAILABLE — … faction music and voices, downloaded
  once") and never downloads without a tap unless the player previously accepted.
  Declining leaves the panel; the game plays. Note the offer is for **every**
  missing pack at once — on a fresh device that is music + voice, **21.3 MB**, not
  5.19 MB, and `PACK_WANT = ['music', 'voice']` downloads the 16.11 MB of music
  first, so KEEN does not become audible until the whole soundtrack has landed. A
  music failure does not block voice (the loop continues), but the ordering does
  delay it. Swapping those two words is the cheapest improvement available here
  and belongs to whoever owns `src/`.
- **Offline.** `netAllowed()` is checked before both the index fetch and the
  download. Offline mode, or a phone that reports itself offline, means no request
  is made at all — not a request that fails.
- **Download fails.** State goes to `error`, the panel reads "AUDIO PACK
  UNAVAILABLE — Download failed — the game runs without it", the button becomes
  RETRY. Partial progress is kept: files already stored are not re-fetched.
- **What they lose.** On a **fresh install** of 1.32.41, nothing: the bank is also
  packaged at `assets/audio/voice/`, and `audLoad()` falls through to that path
  when `packURL()` returns null. On a **device updated over the air from an older
  package**, the packaged bank does not exist, so KEEN and the unit radio fall back
  to `speechSynthesis` — which speaks on iOS after a gesture and is silent on
  Android WebView. Those players get the on-screen line and the walkie-talkie
  squelch, and no speech. That is the whole reason to publish the pack.

## Size, and whether to split it

5.19 MB packed, 324 files, both containers.

| | takes | ogg | m4a | both |
| --- | --- | --- | --- | --- |
| KEEN | 54 | 1.54 MB | 1.71 MB | 3.24 MB |
| ascendancy | 27 | 0.28 MB | 0.26 MB | 0.54 MB |
| syndicate | 27 | 0.27 MB | 0.24 MB | 0.51 MB |
| horde | 27 | 0.25 MB | 0.21 MB | 0.46 MB |
| nova | 27 | 0.23 MB | 0.20 MB | 0.43 MB |
| **total** | **162** | **2.56 MB** | **2.63 MB** | **5.19 MB** |

**Splitting is worth doing, but by format before faction, and neither can be done
without a change to `src/assetpack.js`.**

- **By container — saves ~2.6 MB, half the download.** Every device decodes exactly
  one container and throws the other away, so half of what a phone downloads can
  never be played on it. This is the largest single saving available and it is
  lossless: nothing a player might want goes missing. It needs `PACK_WANT` to be
  chosen at runtime from `audExt()` rather than being a static list, and
  `packURL('voice', …)` in `src/audio.js` to address the right pack. The ordering
  is the catch: `packStart()` runs 4 s after boot and `AUD.ext` is set in
  `initAudioSamples()`, so the format must be resolved (or `audExt()` called
  directly, which is cheap and has no dependencies) before the pack is requested.
- **By faction — saves a further ~0.8 MB (2.56 MB → 1.82 MB).** A player only ever hears their
  own faction's radio: `voPrewarm()` pulls one faction at match start and
  `radioFaction()` resolves to the player's. So `keen + one faction` in one
  container is 1.82 MB, about a third of the current pack. But it needs a pack
  fetched *mid-session* when the player picks a faction they have not downloaded,
  and the first match with a new faction would be radio-silent until it lands.
  Worth doing only after the format split, and only if 2.6 MB is still judged too
  much.
- **Not worth doing: splitting KEEN from radio as separate always-fetched packs.**
  Two requests, same bytes.

Until then, one pack is the honest option: it is complete, it is verifiable, and a
partial pack is silence a player cannot diagnose.

Note that the 216 voice files already on the channel are an earlier render at
different sizes, so every player who took that pack re-downloads the full 5.19 MB
rather than only the 108 new KEEN files. That is the size-keyed cache working
correctly, not a bug.
