# MASSFRONT Ground Kit v1

Roads, plazas, terraces and level changes on the same 32 m grid as the
[building](../mf-modular-building-v1/README.md) and
[superstructure](../mf-superstructure-v1/README.md) kits, in the same material
language. **12 tiles × 3 style sets = 36 modules.**

Generated by [`tools/blender/build-mf-ground-kit.py`](../../../../../../../tools/blender/build-mf-ground-kit.py),
which imports the building kit's geometry vocabulary rather than copying it.

## Why this kit exists

In the reference art the ground plane does an enormous amount of the work:
paved terraces at several levels, retaining walls, wide steps, and above all a
dense rectilinear pattern of **inset groove lines** across every paved surface.
A city of good buildings standing on a flat untextured plane still reads as
greybox. The repo's existing `mf-modular-road-v1` predates this art direction
and does not match it.

## The ground contract is the inverse of the building one

| | Buildings | Ground |
| --- | --- | --- |
| Party plane | must **not cross** it; stops `0.06 m` short | must **land on it exactly** |
| Joint | `0.12 m` recessed reveal between neighbours | **none** — tiles abut |
| Corner treatment | chamfered octagonal masses | **square boxes** |

A building that oversails its cell punches into its neighbour. A ground tile
that stops 5 cm short shows a crack the length of the street. And paving slabs
are deliberately *boxes*, not the chamfered octagons every other mass in these
kits uses — a chamfer would open a hole where four tiles meet.

`verify_ground` checks CROSS, SHORT and LOD monotonicity on all 36 tiles at all
3 LODs. It caught three clamping errors: verge service covers running off the
north edge, ramp treads whose overlap padding pushed them past the tile, and
paving bays sized for a full tile being placed on the ramp's 3 m side strips.

## Datums

| | |
| --- | --- |
| Paving surface | `z = 0` — level with building plinths |
| Terrace drop | `6 m` per level change |
| Carriageway | `20 m`, matching `mf-modular-road-v1` and the 20 m gate clearances in both other kits |
| Kerb | `0.5 m` |

Every edge socket declares `mf_edge_z`, so a placer never butts a grade tile
against the low side of a terrace edge. Road tiles declare `mf_road_arms` so a
placer knows which edges carry a carriageway.

## Build

```bash
blender --background --factory-startup --python tools/blender/build-mf-ground-kit.py
```

Note that **Blender exits 0 even when the script raises** — check the log for
`Traceback` rather than trusting the exit code. That trap cost a full silent
run here (a missing `service` material role killed it after zero output).

## Evidence

Three views per tile (`iso_ne`, `top`, `edge`), one overview per style, and
four **tiling proofs** rendered as 3×3 patches in isometric and plan:
`street_grid`, `terrace`, `service_yard`, `dead_plaza`.
